Part 1 · 产品需求文档 PRD

1.1 产品概述

Vela Term 是一款自用优先的桌面 SSH 终端,整合远程连接、文件传输、密钥管理与多设备云同步。核心主张:本地优先、端到端加密、开箱即连——所有数据先落本地,同步是可选增量;私钥永不明文离开设备。

维度定义
目标用户管理 3–20 台服务器的个人开发者 / 运维;多设备(工作机、家用机、手机)切换频繁
平台macOS / Windows / Linux 桌面(Tauri);移动端只读伴侣(远期)
竞品参照Termius(云同步付费墙)、iTerm2(无同步)、Tabby(重但松散)——Vela Term 取三者交集:轻、快、可同步
成功指标冷启动 < 1.5s;新主机从创建到连上 < 30s;换新设备恢复全部配置 < 2min

1.2 目标与非目标

  • 目标:单窗口完成 连接 → 操作 → 传文件 → 转发端口 的全链路;配置类数据全量可同步;密钥全生命周期(生成/导入/分发公钥/加密同步)。
  • 非目标(v1):团队协作与共享保险库;Mosh/串口/Telnet;内建代码编辑器;AI 命令补全。

优先级:P0 = v1 必须 · P1 = v1 应有 · P2 = 后续版本。编号与原型页面一一对应。

1.4 关键用户流程

  1. 首次接入:新建主机 → 选择/生成密钥 → 复制公钥到服务器 → 连接成功 → 配置自动进入同步集。
  2. 日常部署:⌘K 搜主机连接 → 运行片段「重启网关」→ 切到传输页上传制品 → 队列完成通知。
  3. 换新设备:登录 + 输入主密码 → 拉取加密同步集 → 本地解密 → 主机/密钥/片段全部就位。

1.5 非功能需求

类别要求
安全私钥仅以密文出本机;主密码不上传;同步服务零知识(见 3.4);剪贴板复制公钥 60s 后自动清除敏感项
性能终端渲染 ≥ 60fps(WebGL);SFTP 单流吞吐 ≥ 80% 原生 scp;同步一次往返 < 2s(100 条配置)
离线全功能离线可用(除同步);离线变更排队,联网后自动合并
可靠崩溃不丢会话历史缓冲(落盘环形缓冲);传输中断可续传

2.4 状态与数据流

  • 配置类数据(主机/密钥元数据/片段/规则)由 Rust 侧 SQLite 持有,前端经 IPC 读写,store 仅做缓存;前端不落盘敏感数据。
  • 流式数据(终端输出、传输进度、延迟探测)走 Tauri 事件通道,store 增量合并,组件按会话 ID 订阅。
  • 主题、侧栏收缩、字号等纯 UI 偏好存 localStorage,并入 F7「设置」同步项。

2.5 IPC 契约(前端 → Rust)

命令说明
session.open(hostId)建立 SSH 会话,返回 sessionId;输出经 term://data/{id} 事件流
session.write(id, bytes)写入终端输入(含粘贴护栏:多行粘贴需确认)
sftp.list(id, path) / sftp.enqueue(job)目录列举;入队上传/下载,进度事件 transfer://progress
keys.generate(algo) / keys.import(pem)密钥生成/导入;私钥只返回句柄,永不返回明文
forward.start(rule) / forward.stop(id)启停转发;流量统计事件 forward://stats
sync.push() / sync.pull()手动同步;状态事件 sync://state

快捷键注册于壳层(⌘K 面板、⌘T 新标签、⌘1–9 切换、⌘U 上传),终端焦点内的按键优先透传远端,仅拦截显式绑定项。

Part 3 · 后端开发文档

3.1 架构总览

后端分两部分:本地核心(Rust,随 App 进程)承担全部 SSH/SFTP/加密工作;同步存储直接采用 S3 兼容对象存储(AWS S3 / Cloudflare R2 / MinIO 均可)——无自建服务端,桶内只有密文,凭据由用户自备。

┌─ 桌面 App ──────────────────────────┐
│ React UI ── IPC ── Rust 核心         │
│                    ├─ russh (SSH/SFTP/转发)
│                    ├─ SQLite (配置/片段/录制索引)
│                    ├─ Keychain (主密码派生密钥缓存)
│                    └─ Sync Engine ──S3 API──▶ S3 兼容桶
└─────────────────────────────────────┘         ├─ manifest.json (版本向量, 密文)
                                                ├─ oplog/{device}/{seq}.bin (密文条目)
                                                └─ blobs/{id} (录制等大文件密文)

3.2 本地核心模块

模块职责与要点
ssh基于 russh;每会话独立 task;keepalive 15s;断线指数退避重连(1/2/4/8s,上限 5 次)
sftp并发窗口 4 个 64KB 块;续传按「大小 + mtime + 前 1MB 哈希」校验;队列持久化,崩溃后恢复
forwardL/R 直连转发与 D 类 SOCKS5;规则绑定宿主会话,重连后自动重建;按规则聚合字节计数
vault密钥库:生成(ed25519 / rsa4096)、导入、指纹(SHA256);私钥密文存 SQLite,解密仅在内存,zeroize 擦除
recorderPTY 输出旁路写 asciicast v2(逐条 flush);索引入库,正文为文件
sync变更捕获(SQLite 触发器写 oplog)→ 加密 → PUT 到桶内本设备前缀;拉取端 LIST 其他设备前缀增量下载,按实体 LWW 合并,冲突留双副本标记

表关键字段

3.4 加密方案(零知识)

  1. 主密码 → Argon2id(m=256MB, t=3)派生 MK,仅存内存与系统 Keychain(可选,受生物识别保护)。
  2. MK 包裹随机 Vault Key(密钥项)与 Config Key(其余配置),分层可轮换。
  3. 数据项以 XChaCha20-Poly1305 加密,AAD 绑定 entity + id + lamport 防重放错位。
  4. 桶内仅存密文对象与加密的版本向量,S3 服务商无法解读;恢复短语(BIP39,24 词)可在无旧设备时重建 MK。忘记主密码且无短语 = 数据不可恢复,产品内明确提示。

3.5 S3 同步协议(无服务端)

对象 / 操作说明
manifest.json(PUT If-Match)加密的版本向量与设备清单;以 ETag 条件写实现乐观锁,冲突则重读重算
devices/{device_id}.json设备注册信息(名称、公钥、加入时间);新设备写入后需在既有设备上批准或用恢复短语
oplog/{device_id}/{seq}.bin每设备单调递增序号的密文 oplog 条目,天然幂等;只追加,不覆写
blobs/{id}录制等大文件密文,分片上传(multipart)
拉取:LIST oplog/* since 本地游标按 device_id + seq 增量下载并合并;各设备游标存本地
压实:合并 30 天前 oplog → snapshot任一设备可执行;写 snapshot/{lamport}.bin 后删除旧条目

合并策略:实体级 LWW(lamport 时钟);密钥项删除采用墓碑保留 30 天。凭据建议使用仅限该桶前缀的最小权限 IAM Key(GetObject / PutObject / ListBucket / AbortMultipartUpload),存系统 Keychain;移动网络下仅同步小对象,大文件延后。

3.6 安全与合规清单

  • 已知主机指纹(known_hosts)本地校验,首次连接显示指纹确认;变更即中断并警示。
  • 内存中私钥与派生密钥使用 zeroize;禁止进入崩溃转储(madvise(MADV_DONTDUMP))。
  • 日志脱敏:不记录命令内容与文件名,仅记录事件类型与耗时。
  • 依赖审计:cargo audit / npm audit 进 CI;同步服务季度渗透测试。
