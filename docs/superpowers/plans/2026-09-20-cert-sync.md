# 证书接入云同步 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `cert` 接成一等同步实体,证书本体、证书私钥与 ACME 账户密钥经主密码端到端加密跨设备同步,自动续期由单一归属设备负责。

**Architecture:** 照抄 `key` 实体的既有范式 —— 出网时把设备密钥层解成明文、整条 WireOp 由主密钥 `seal`(AAD 绑对象路径),入网时用本机设备密钥重新加密落库。加密层次不变。新增独立 `certs` 同步范围(默认开),复用平台 `key_sync` 开关。`certs` 表加 `owner_device_id`,`spawn_renew_loop` 只处理归属本机的证书。

**Tech Stack:** Rust(rusqlite、chacha20poly1305、tokio)、React 18 + TypeScript、Zustand。

**Spec:** `docs/superpowers/specs/2026-09-20-cert-sync-design.md`

## Global Constraints

- 加密层次不变:证书密文在库内始终是**设备密钥**加密(`account_key_enc` / `key_pem_enc` 两列),只在出网瞬间解成明文并由主密钥整体 `seal`。
- `apply_wire` 只能调 `*_raw` 写入函数(不写 oplog),否则远端条目会被当本地变更推回,形成回环。
- 平台功能开关仍为 **11 项**,本计划不新增;证书同步复用 `key_sync`。
- `certs` 表已存在于存量库,新列必须经幂等补列加入 —— `db.rs` 只有 `CREATE TABLE IF NOT EXISTS`,改建表语句对存量库无效。
- `SyncScopes.certs` 用 `#[serde(default = "default_true")]`;`#[serde(default)]` 对 `bool` 取 `false`,会让存量配置静默关闭证书同步。
- 提交信息用中文,遵循仓库既有的 `fix(scope):` / `feat(scope):` 约定,末尾附 `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`。

```rust
/// 幂等补列。`open()` 里只有 `CREATE TABLE IF NOT EXISTS`,改建表语句对存量库无效,
/// 已建好的表要加列只能走这里。table/column/decl 均为代码内字面量,不接受外部输入。
fn add_column_if_missing(conn: &Connection, table: &str, column: &str, decl: &str) -> Result<()> {
    let mut stmt = conn.prepare(&format!("PRAGMA table_info({table})"))?;
    let exists = stmt
        .query_map([], |r| r.get::<_, String>(1))?
        .any(|c| c.map(|name| name == column).unwrap_or(false));
    drop(stmt);
    if !exists {
        conn.execute(&format!("ALTER TABLE {table} ADD COLUMN {column} {decl}"), [])?;
    }
    Ok(())
}
```

```rust
    fn claim_unowned_certs(&self) -> Result<()> {
        let device = self.device_id();
        let conn = self.conn.lock().unwrap();
        conn.execute(
            "UPDATE certs SET owner_device_id = ?1 WHERE owner_device_id = ''",
            [device],
        )?;
        Ok(())
    }
```

```rust
    pub fn cert_payload(&self, cert_id: &str) -> Result<String> {
        use base64::Engine;
        let b64 = base64::engine::general_purpose::STANDARD;
        let row = self.get_cert_full(cert_id)?;
        Ok(serde_json::to_string(&serde_json::json!({
            "meta": {
                "id": row.id,
                "domains": row.domains,
                "challenge": row.challenge,
                "ca": row.ca,
                "hostId": row.host_id,
                "deployPath": row.deploy_path,
                "reloadCmd": row.reload_cmd,
                "notAfter": row.not_after,
                "autoRenew": row.auto_renew,
                "state": row.state,
                "ownerDeviceId": row.owner_device_id,
                "createdAt": row.created_at,
            },
            "certPem": row.cert_pem,
            "chainPem": row.chain_pem,
            "accountKeyDevEnc": row.account_key_enc.as_ref().map(|b| b64.encode(b)),
            "keyPemDevEnc": row.key_pem_enc.as_ref().map(|b| b64.encode(b)),
```

```rust
/// cert 实体 payload:设备密钥层 → 明文(随后整条经主密钥加密出网)。
/// 两列都可能为空(签发未完成的证书),空则原样跳过。
fn cert_payload_plaintext(vault: &Vault, p: &mut serde_json::Value) -> Result<()> {
    for (enc_field, plain_field) in
        [("accountKeyDevEnc", "accountKey"), ("keyPemDevEnc", "keyPem")]
    {
        let Some(enc) = p[enc_field].as_str().map(str::to_string) else {
            p.as_object_mut().unwrap().remove(enc_field);
            continue;
        };
        let raw = vault.decrypt(&b64().decode(&enc).map_err(|e| AppError(e.to_string()))?)?;
        p[plain_field] = serde_json::Value::String(
            String::from_utf8(raw).map_err(|_| AppError("证书密文解码失败".into()))?,
        );
        p.as_object_mut().unwrap().remove(enc_field);
    }
    Ok(())
}
```

```rust
        deploy_path: "/etc/ssl/sync".into(),
        reload_cmd: "nginx -s reload".into(),
        not_after: 1_900_000_000_000,
        auto_renew: true,
        state: "active".into(),
        account_key_enc: Some(v_a.encrypt(acct).unwrap()),
        cert_pem: Some("LEAF-SYNC".into()),
        chain_pem: Some("CHAIN-SYNC".into()),
        key_pem_enc: Some(v_a.encrypt(key_pem.as_bytes()).unwrap()),
        owner_device_id: dev_a.clone(),
        created_at: "2026-09-20".into(),
    })
    .unwrap();
    sync::sync_once(&db_a, &v_a).await.unwrap();
    sync::sync_once(&db_b, &v_b).await.unwrap();

    let b_cert = db_b.get_cert_full("cert-sync-1").expect("B 应收到证书");
    assert_eq!(b_cert.cert_pem.as_deref(), Some("LEAF-SYNC"), "证书本体应一致");
    assert_eq!(b_cert.owner_device_id, dev_a, "归属应仍是 A");
    assert_eq!(
        v_b.decrypt_current(b_cert.key_pem_enc.as_deref().unwrap()).unwrap(),
        key_pem.as_bytes(),
        "B 应能用自己的设备密钥解开证书私钥"
    );
    assert_eq!(
        v_b.decrypt_current(b_cert.account_key_enc.as_deref().unwrap()).unwrap(),
        acct,
        "B 应能用自己的设备密钥解开 ACME 账户密钥"
    );

    // B 接管:改写归属并回同步,A 应让出
    let mut taken = b_cert.clone();
    taken.owner_device_id = db_b.device_id();
    db_b.upsert_cert(&taken).unwrap();
    sync::sync_once(&db_b, &v_b).await.unwrap();
    sync::sync_once(&db_a, &v_a).await.unwrap();
    assert_eq!(
        db_a.get_cert_full("cert-sync-1").unwrap().owner_device_id,
        db_b.device_id(),
        "A 应看到归属已转给 B"
    );
    println!("step11 证书跨设备同步 + 归属接管 OK");
```
